# 群投递背压修复 · 2026-10-30

本地修复完成，默认容量仍为 16，未部署。32/64 人继续允许显式创建实验群。本报告延续上一轮同机模拟节点负载，不能代表异网 NAT 或公网中转容量。

## 改动

- 入站处理仍限制 32 个并发，满载等待空位，替代直接拒绝连接。
- 每节点群投递最多 4 个并发；后台补投最多占一个槽。消息 ID 与收件人组成在途锁，避免首次发送与后台重试重复竞争。
- 群与私聊补投独立调度。群队列按上次尝试时间公平选择、临时故障退避 4～30 秒；显式 retry 可跳过退避。新增调度字段通过兼容迁移保留已有消息与状态。
- 每次发送和接收仍向群主重新校验权限，没有缓存授权或放松撤权规则。

## 确认复测

同一个 Release 文件再次跑完三档，仍然全部请求受理、最终送达率 100%，没有入口拒绝。并发全员 ACK P95 分别为 0.181 / 0.366 / 1.064 秒；串行 P95 为 0.227 / 0.292 / 0.771 秒。私有内存采样峰值合计分别为 124.5 / 279.9 / 445.7 MiB。

第二轮 16 人测试早期与安装器验证短暂重叠，主机后台负载也有变化，因此保留两轮各自结果，不合并成一个百分位。两轮共 144 条负载消息、5,232 次目标收件投递全部送达；18 次群主离线尝试均拒绝且未落盘，6 次恢复广播全部送达。

## 离线行为

**群主离线：其他人目前不能发新群消息。** 三档共 9 次尝试全部约 8 秒后失败，未经校验的消息未落盘；原群主恢复后，成员保持，三次恢复广播全部送达。P2P 传输并不必然要求群主在线，这是当前实时权限协议的选择。

**普通成员离线：在线成员照常接收，离线成员的副本保存在发送方本地 SQLite pending 队列。** 对端恢复且群主在线后自动补投；落盘 ACK 后标记 acked，接收按 ID 去重。发送方退出时暂停，重启继续。如果发送方永久离线或丢失数据，当前没有其他节点或云端代存恢复。

暂存重试没有群消息 TTL、队列配额或自动清理；ACK 不会自动删除本地消息历史。移除、禁言、解散或屏蔽等永久拒绝使投递成为 rejected，恢复权限不会自动复活。已授权的在途消息不承诺撤回。
