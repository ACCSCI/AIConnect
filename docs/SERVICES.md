# Local service collaboration

`service.*` is authenticated local daemon IPC. Jobs live in the existing profile's SQLite database; there is no hosted job server. A job proposal does not start an agent or authorize an operating-system command.

`service.invoke` accepts `transport` (`native` or `a2a`), `audience`, `capability`, `input`, `grantId`, `idempotencyKey`, `declaredPrice: {amount: 0, currency: "USD"}` and optional `ttlSeconds` (1–86400). Native requests also require an existing persistent `sessionId`, whose peer must equal `audience`. A2A requests require `provider` equal to `audience` and an unexpired, explicitly attested free provider registration. Unknown and positive prices fail closed. Local price attestations are not independently verified pricing or a payment guarantee.

An owner delegation must target this device, the exact audience and scope `service:<capability>`. Expiry, owner pinning, revocation freshness and max-call limits apply. Input SHA-256 covers RFC 8785 JCS bytes. Native service invocation requires a fresh signed `descriptor`, supplied explicitly or obtained from the discovery cache. It must belong to the target and advertise the requested capability with an input schema and an explicit free price. These constraints are enforced; conflicting signed content at the same cached revision is rejected. An additional caller input schema can only further restrict it. Remote schema references are disabled. Without a descriptor, use `tasks.propose` for a human-reviewed task; `service.invoke` refuses to bypass advertised capability validation.

The database reserves the idempotency key before consuming a grant or resource budget. Identical repeated requests return the same job; conflicting reuse is rejected. Authorization interrupted by a crash leaves a non-dispatchable record rather than silently trying again. Native job IDs are the workflow proposal event/task IDs. Native task acceptance, delivery and requester approval remain separate states.

For outbound A2A, `service.dispatch {jobId}` revalidates the grant and free provider policy, then atomically claims a queued job. A second claim fails; a crash after claiming does not cause an automatic side-effecting resend. The local SDK bridge records provider events using `service.update`, with `providerStatus` of `submitted`, `working`, `input-required`, `completed`, `failed` or `canceled`. Provider `completed` maps to local `delivered` / `awaiting_review`. `service.review {jobId,approve,text?}` performs requester review. Artifact manifests contain a name, SHA-256 and size; manifests are declarations, not proof that an artifact was downloaded or independently hashed.

`service.cancel` immediately cancels an A2A job that has not been dispatched and releases its concurrency reservation. After dispatch, or for an existing native workflow task, cancellation records a request and cannot promise rollback of external effects. Resource call/turn counters are not refunded. Expired jobs cannot dispatch. Optimistic database revisions prevent concurrent cancellation, snapshots and delivery updates from silently overwriting each other.

`service.status` / `result` query a job; `service.list` and `pending` scan up to 32 rows / 300 KB per page using `offset`, `nextOffset`, `hasMore` and optional `transport`. Filtering applies within a scanned page, so clients must follow `hasMore` even when a page is empty. `service.lookup {externalTaskId}` and `service.snapshot {jobId,externalTask}` support the optional local SDK TaskStore. A snapshot never changes a native task's actual workflow state. These mutation APIs are for trusted local adapters and must never be exposed as unauthenticated remote endpoints.

Network interoperability, provider DNS/SSRF checking and protocol authentication remain responsibilities of the bridge at the actual HTTP boundary. Declaring an A2A transport in a local job does not make native iroh packets an A2A HTTP transport. No model calls, paid relay subscriptions, cloud account signup or production deployment are triggered by these APIs.
