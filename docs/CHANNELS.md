# Channels

Channels separate publication from execution. Private channels reuse owner-signed group snapshots and member replica delivery. A new member joins as a reader (`canSend: false`); the owner can grant publication with `channels.publisher`. The same permission is checked by raw `groups.send` and signed-record ingestion. These are small private channels, with the existing group member ceiling, not large public broadcast fanout.

Public channels run locally. `channels.publish` creates an author-signed event with a sequence and previous-signature reference. `channels.export` returns two static file bodies: `channel.json` (signed manifest containing signed events) and `feed.json` (an unsigned JSON Feed mirror). Nothing is uploaded and no hosting API is called. The producer retains 64 events; an export may include fewer to keep its complete IPC response under 900 KB. Consumers explicitly report a missing historical range. This is authorship verification, not consensus or proof of a wall-clock publication time.

Consumers use `channels.subscribe` to save an HTTPS URL, then `channels.sync` to fetch it immediately. The origin must first pass the shared free-provider policy. HTTP requests use the governance module's DNS-pinned public-HTTPS fetcher, bounded response bodies, no redirects/proxies, conditional headers and per-source persistent polling backoff (one minute after success, exponential backoff after failure). `channel_tick` lets the daemon poll at most one due explicit subscription per tick; unsubscribed sources are excluded. `channels.import` accepts a downloaded/static file body for offline use and tests. Ordinary RSS/Atom/JSON Feed imported this way is marked `unverified_local`; fetched feeds are `https_source`, never author-signed.

For native signed manifests, supply `expectedPublisher` while subscribing to pin an already-known author. Without it, the first signed import establishes a TOFU key pin, labeled `tofu_not_owner_verified`. A pinned author cannot be silently replaced; signed sources cannot downgrade to unsigned feeds. Channel IDs, event IDs, event sequences, signatures, chain links, manifest tail and rollback are checked. Read cursors and event deduplication survive daemon restarts. A stable ordinary feed entry ID is treated as already seen, even if its text is later edited. Each source retains at most 5,000 received events; retention removals are reported.

`channels.read {sourceId}` advances a subscription's read cursor; `after` supports explicit replay of retained events. `channels.notifications {after}` supplies a separate bounded event stream for CLI watch (32 events and at most 350 KB per page), filtered to active, unmuted subscriptions. `channels.mute` suppresses this stream and the returned `notificationsReady` count. `channels.unsubscribe` disables subsequent imports and network sync, revokes its notification wake permission, and retains local history for inspection. A notification count/event stream is readiness metadata, not a claim that an OS notification was displayed.

Runtime notification is **off by default** (`wake: false`). The local user may explicitly enable it with subscription `wake: true` or `channels.wake {sourceId,wake:true}`. Enabling records a current-event baseline and does not replay earlier history. An attached trusted adapter must use `read-only`; `workspace-write` attachments are rejected for notifications. The runtime sends a separate `kind: channel_notification`, with `permissions: {wake:true,notification:true,task:false}`, one model turn and at most 30 seconds. Both attachment and source permissions are rechecked immediately before invocation. Native blocked authors, private revoked publishers, muted/unsubscribed sources and historical private epochs are rejected. The adapter receives channel content as untrusted data for a local summary, never as a task grant. Results remain in the local claim journal; the runtime sends no reply to the channel or private chat. Invocation uses durable pre-launch claims/cursors and the governance execution budget, so restart does not silently repeat an uncertain invocation. This is an adapter contract on a trusted host, not a new OS sandbox for malicious local executables.

Request actions: `channels.create`, `list`, `show`, `invite`, `join`, `publisher`, `publish`, `export`, `subscribe`, `subscriptions`, `sync`, `import`, `read`, `notifications`, `wake`, `notification.authorize`, `mute`, `unsubscribe`. The generic authenticated CLI `request` interface can access the complete JSON contract. Use `channelId` for owned/native channel operations and `sourceId` for subscriptions. `visibility` defaults to `private`.

No central channel database, paid relay, cloud mailbox, auto-deployment or paid service fallback is introduced. A private channel still requires a reachable member replica to obtain missing messages. Existing partition/revocation limitations of signed group snapshots continue to apply.
