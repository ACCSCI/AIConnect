# AIConnect distribution website

Cloudflare Workers Static Assets target in **asset-only mode**: `wrangler.jsonc` has no `main`, asset binding, or `run_worker_first`. This is a distribution/documentation site, never a messaging relay or user account backend. No deployment has been performed during local development.

```powershell
cd site
npm ci
npm run check
npm test
npm run test:local
npm run dev
```

Local site: `http://127.0.0.1:8787`. The `build` step copies available bootstrap helpers from `../distribution/`; no published artifact or release manifest is fabricated. A real manifest must be generated by the distribution tooling from actual binaries and signed before a public installation is enabled.

`npm run bundle:check` creates a local Wrangler dry-run bundle only. There is deliberately no publish/deploy script. Do not run a real `wrangler deploy` before the human's release gate.

The well-known discovery schema is the static `{skills:[{name,description,files}]}` format; the listed files must all exist and be downloadable. `build` also copies `../adapters/codex-app-server.mjs` unchanged as a Skill-local optional Agent bridge. The native messaging binary has no Node.js dependency; this optional bridge does. `test:local` starts a real Wrangler/workerd local server, verifies HTTP headers/routes, uses the pinned official `skills@1.7.4` CLI to discover the skill, and installs it in a fresh project under `.local/skill-install-*`. It compares every installed resource against its served source bytes; no global skill directory is modified. Skill installation is not execution of the bootstrap script.

Static `_headers` sets security, MIME, CORS and caching headers. `/healthz` is a static JSON distribution marker, **not** a live Agent/network/backend health probe. Missing API and download paths receive a natural static 404, not a dynamic Worker response or single-page fallback. `src/worker.js` is retained only as an unused historical example; neither production configuration nor local integration tests load it.

This configuration avoids user Worker invocation for health/API routes. Cloudflare documents [asset-only configuration without a script](https://developers.cloudflare.com/workers/static-assets/binding/) and [static asset header rules](https://developers.cloudflare.com/workers/static-assets/headers/). Static asset requests are currently [free and unlimited](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/); dynamic Worker execution has separate billing rules and is not enabled here. The project's only authorized website spending remains its domain and static hosting. No Cloudflare KV, D1, R2, Durable Object, or paid relay is configured.
